## Next

- [ ] **Nothing pins the number of `step()` calls to the total the progress bar is told.** *(code review, 2026-08-18)* `performLinuxRestore()` makes exactly 10 calls and `LinuxRestoreStepCount` is 10; `WindowsDiskService::restore()` makes 14 and `totalRestoreSteps()` returns 14. Both verified by counting, neither by a test. `HelperReporter::step()` clamps to the declared count, so adding a step makes the bar stick at full while work continues, and no test fails. A fake reporter that counts calls through one restore would hold both. Since 2026-08-20 the same applies to `firstDestructiveStep()` (both backends: step 5), which the stall notice uses to say whether unplugging is still safe — being wrong there is worse than a stuck progress bar, so the fake-reporter test should pin it too. One more reason a test matters: the GUI answers `firstDestructiveStep()` from its own build, but the steps are announced by whatever helper binary is installed — a version skew between the two would shift the boundary silently, and only a pinned count would notice.
- [ ] **Windows: a cancel after “Detaching existing drive letters” reports “the disk was not changed”.** *(code review, 2026-08-20; pre-existing, not a 1.5.0 regression)* True about the stick itself — the checkpoint sits before the first write to the disk — but the drive letters are already gone from the mount manager’s database, so “not changed” overpromises. The message should say the letters may need to be reassigned, or the cancel path should restore them. Display wording only; no safety rule involved.
- [ ] **Distribution packages** (`.deb`, `.rpm`, AUR). Privilege separation only works when the helper and the polkit policy are installed to system paths. The AppImage cannot do that. Packaging is why this is 1.3.0 and not 1.2.0. See [[Linux]] and [[Releases]].
- [ ] **Windows Authenticode signing** for releases, if a certificate is available. Unsigned builds work; they show "Unknown" publisher and may trip SmartScreen. See `docs/signing.md` and [[Releases]].
- [ ] **Linux sector-size matrix.** Unit tests and `verify-partition-tables.sh` cover 512 and 4096. Confirm a 4K-native stick on hardware if one is on hand.

## Later

- [ ] **macOS.** Out of scope until someone implements `DiskService` and nothing else. Do not teach `src/core` or the GUI about Darwin.
- [ ] **AppImage + polkit.** Fundamentally blocked: polkit reads policies from system directories, which a self-contained bundle cannot register. Do not spend design time on a workaround that reintroduces trusting the caller.
- [ ] **Windows privilege split.** Deliberately not done. UAC already gates the process at launch; a service or COM elevation moniker would add more attack surface than it removes. See [[Decisions]].

- [x] **A cancel during the pkexec handoff can no longer report "cancelled" while the helper restores the disk** — 2026-08-19. The old code answered a pre-version-line cancel with `process.kill()` and believed it: but once pkexec authenticates and execs the helper the process is root, the unprivileged GUI's SIGKILL fails silently, and the run used to finish the whole restore while being reported as "cancelled — the disk was not changed". - [x] **Pre-check filesystem geometry on Linux before erasing anything** — 2026-08-18. `canFormatFileSystem()` no longer returns `true` from every case; the FAT32 case is checked against `mkfs.vfat`'s real limits and the refusal tail is reachable. **The original finding had the failure mode wrong**: dosfstools 4.2 refuses neither edge. An explicit `-F 32` waives its own minimum-cluster rule (`mkfs.fat.c:898`) so an undersized volume gets a warning and an out-of-spec filesystem, and an oversized one is clamped to `UINT32_MAX` sectors (`mkfs.fat.c:780`) so the end of the disk is silently left unused. The check lives in `linux_restore.cpp` so the helper re-applies it to the disk it re-derived, rather than trusting the GUI. ## Rules for this list

- A safety-rule change is not done until `tests/test_core.cpp` covers the case it now refuses.
- A new partition layout is not done until `scripts/verify-partition-tables.sh` has a case for it.
- Do not add a GUI command-line flag that starts a restore.
- Do not widen the USB bus-type check.
- Do not add a bypass for the acknowledgement dialog or the identity check.
- The vault is published with the repository. No usernames, hostnames, home paths, device serial numbers or other personal identifiers in entries — describe hardware by model and size, and people by role ("the desktop user").
